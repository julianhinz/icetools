# CLAUDE.md — icetools

R package defining and implementing the `.ice` / `.icc` file formats for
initial conditions of quantitative trade models. Public face:
https://icefil.es (repo `~/Repositories/icefil.es`) — the site and this
package are one project; keep branding and cross-links consistent.

## What this package is

- `.ice` = gzip tar of per-table CSVs + `metadata.yaml` (+ `scalars.csv`).
  Spec: `docs/ice-schema.md` (format version 1.1).
- `.icc` = compiled cache of a `.ice` (dense arrays, qs2-or-RDS).
  Spec: `docs/icc-schema.md` (format version 1.0).
- Exported API: `create_metadata`, `generate_ice`, `read_ice`,
  `validate_ice`, `list_tables`, `extract_table`, `build_manifest`,
  `sha256_file`, `compile_ice`, `read_icc`, `validate_icc`, `icc_tables`.

## Hard rules

1. **Backward compatibility**: `.ice` files written by icetools 0.1.2
   (all published KITE-data releases) must keep reading correctly.
   `tests/testthat/fixtures/v012_fixture.ice` was generated by the exact
   vendored 0.1.2 sources — never regenerate it with newer icetools
   (`fixtures/make-v012-fixture.R` documents how it was made).
2. **Schema changes bump the format version** (`ICE_FORMAT_VERSION` /
   `ICC_FORMAT_VERSION` in `R/utils.R`) **and update the schema docs**
   (`docs/*.md`, incl. the version-history table). Format changes are
   additive within a major version.
3. **The numeric round-trip guarantee is enforced, not assumed**: the
   writer re-parses what it writes (see `format_double_shortest()` in
   `R/utils.R` and its comments — R's/fread's decimal parsers are
   imprecise in ways that matter; don't "simplify" this code without
   reading them).
4. This is a package: dependencies via `Imports:` in DESCRIPTION, no
   `library()`/`pacman` in `R/` (CODESTYLE.md's pacman rule applies to
   scripts, not package code). No `[.data.table` j-syntax surprises:
   `.datatable.aware <- TRUE` is set in `R/utils.R`.

## Commands

```bash
Rscript -e 'pkgload::load_all("."); testthat::test_dir("tests/testthat")'  # tests
Rscript -e 'roxygen2::roxygenise()'                                        # docs/NAMESPACE
R CMD build . && R CMD check --as-cran icetools_*.tar.gz                   # full check
```

CI runs R CMD check + tests on push/PR (`.github/workflows/R-CMD-check.yaml`).

## Test conventions

- testthat edition 3; helpers in `tests/testthat/helper-ice.R`
  (`example_components()`, `write_example_ice()`).
- Round-trip tests must be `expect_identical` (bit-exact), not
  `expect_equal`.
- An optional integration test reads a genuine KITE-data artifact: set
  `ICETOOLS_KITE_ARTIFACT=/path/to/artifact.ice` or have staged releases
  in `~/Repositories/KITE-data/releases/staging/`; skips otherwise.

## Release process

1. Update `NEWS.md`; bump `Version:` in DESCRIPTION (semantic
   versioning; dev = `.9000` suffix).
2. Full check clean (`R CMD check`), tests green.
3. Commit, tag `vX.Y.Z`, push with tags, `gh release create`.
4. Remind downstream: KITE-data vendors a sha-pinned tarball at
   `code/dependencies/` (+ MANIFEST) and must re-vendor deliberately —
   do not modify KITE-data from here. KITE-dev should consume `.icc`
   from this package instead of its own copy (migration note in the
   0.2.0 release).

## Ecosystem map

- **KITE-data** builds/validates ICs, publishes `.ice` via GitHub
  Releases (vendors icetools).
- **ricardo-aas** fetches release artifacts.
- **KITE / KITE-dev** consume `.ice`; KITE-dev's fast-solver `.icc`
  implementation (`R/icc.R` there) was ported here — deviations
  documented in `docs/icc-schema.md` §2.1.
- **KITE-projections** carries temporary local ICE helpers slated for
  replacement by `create_metadata(...)`/`generate_ice(validate=TRUE)`/
  `build_manifest()` (issue #2).
