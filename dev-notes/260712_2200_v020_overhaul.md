## Key decisions

- **Numeric round-trip is enforced at write time**, verified against
  the reader's own parser. Findings that shaped this (all reproduced,
  see comments in `R/utils.R` and the fuzz test): fwrite writes ~15
  significant digits (the 0.1.2 "guarantee" was broken at the 16th);
  base R's parser AND fread can be one ulp off even for a double's
  exact decimal expansion on ARM (trailing-zero mantissas, e.g. runif
  output); R's as.numeric parses normalized subnormal hex as 0 and
  misparses the exact double.xmax decimal as Inf. Resolution ladder:
  %.15g → %.22g decimals verified via fread; whole-column C99 hex-float
  fallback (exact under as.numeric everywhere); subnormals spelled
  0x0.<frac>p-1022. Columns arriving as character (hex mode) are
  coerced by the reader per metadata.
- **Metadata is authoritative on read** (types incl. leading-zero
  character keys); value column = last column, any name; always-double
  guarantee for declared numeric/integer value columns.
- **Scalars**: `scalars.csv` (name,value) + `scalars:` metadata block;
  round-trips the component list shape KITE-data's BF artifacts need.
- **.icc port is faithful to KITE-dev** (cast order, reverse key sort,
  first-wins sorted dimension inventory per #142) with documented
  deviations: last-column-is-value, keyless tables stay vectors,
  elasticity nesting and scenario materialization stay in KITE-dev.
- **validate_ice** collects all problems in one abort; completeness via
  uniqueN product + duplicate check (no expand.grid explosion);
  strictness toggles `check_na`/`check_complete`.
- 0.1.2 fixture generated from the vendored tarball sources and frozen;
  integration test picks up real artifacts from KITE-data staging or
  `ICETOOLS_KITE_ARTIFACT`.
